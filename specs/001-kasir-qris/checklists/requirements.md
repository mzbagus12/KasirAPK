# Specification Quality Checklist: Kasir QRIS dan Laporan Harian

**Purpose**: Memeriksa kesiapan spesifikasi untuk perencanaan.

**Created**: 2026-11-12

**Feature**: [Spesifikasi](../spec.md)

## Content Quality

- [x] Mencatat Android dengan penyimpanan lokal, QRIS toko, perhitungan kembalian, dan konfirmasi pembayaran oleh kasir.
- [x] Berfokus pada pekerjaan kasir dan pemilik toko.
- [x] Dapat dibaca oleh pemangku kepentingan nonteknis.
- [x] Seluruh bagian wajib terisi.

## Requirement Completeness

- [x] Tidak ada penanda klarifikasi terbuka.
- [x] Persyaratan menyatakan perilaku yang dapat diperiksa.
- [x] Kriteria sukses dapat diukur.
- [x] Kriteria sukses tidak bergantung pada pilihan implementasi.
- [x] Skenario penerimaan tersedia untuk setiap alur.
- [x] Kasus tepi mencakup tunai pas atau kurang, pergantian metode dan akun, pemulihan tagihan, QRIS terlambat, serta arsip PDF setelah koreksi.
- [x] Batas cakupan tercantum.
- [x] Dependensi dan asumsi tercantum.

## Feature Readiness

- [x] Persyaratan dapat ditelusuri ke skenario, kasus tepi, atau kriteria sukses.
- [x] Alur penyiapan, pemulihan akun, pembayaran, koreksi admin, nota, dan pengelolaan PDF tiga periode tercakup.
- [x] Kriteria sukses mendefinisikan cara menguji hasil fitur.
- [x] Spesifikasi menyatakan perilaku yang diharapkan dan membiarkan desain teknis terbuka.

## Notes

- Checklist menilai mutu spesifikasi. Pengujian aplikasi dilakukan saat implementasi.
